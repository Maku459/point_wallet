# 実装ログ

いつ何をしたかの記録。新しいものを上に足す。
`docs/knowledge.md` と違って自動では読み込まれないので、
「あの変更いつ入れたっけ」「なぜこの形になったんだっけ」を辿りたいときに開く。

書き方

```markdown
## YYYY-MM-DD 見出し (#PR番号)

- やったこと（1〜3 行）
- 触ったファイル / 分かったことがあれば `docs/knowledge.md` の節名を添える
```

詳しい経緯はコミットメッセージに書いてある。ここでは重ねて書かず、
`git show <hash>` で辿れるように番号とハッシュを残す。

---

## 2026-09-20 状態・単位の絞り込みと期限プリセットを削除する (#4)

- 使っていなかった「状態」「単位」の絞り込みと、編集画面の「1か月後」などの
  プリセットボタンを消した。単位はデータ項目ごと廃止し、合計は単位別ではなく
  ひとつの数字にした（`summarize` の戻り値が `totals` 配列 → `total` 数値）。
  カードの色分け・「あと◯日」バッジ・失効前の通知は残してある。
- `filterEntries` は検索だけになり、`today` 引数が要らなくなった。
  `unit` を持つ古いバックアップを読んでも項目は復活しない（`sanitizeEntry` が落とす）。
  → 知見「外から入ってきたデータは必ず `sanitizeEntry` を通す」
- Service Worker は `v6`。

## 2026-09-20 最終更新日をカードに表示する (#3)

- 登録・編集した日を記録して一覧のカードに出すようにした（`921fae0`）。
  「今日 / 昨日」は暦の上の日数差で判定し、中身が変わっていなければ記録は据え置く。
  記録が無い古いデータは登録日に合わせ、読み込むたびに今日へ動かないようにした。
  → 知見「最終更新日（`updatedAt`）はカードに出ている」

## 2026-09-20 実装ログと知見の置き場所を作る

- `trip_planner` と同じ `CLAUDE.md`（実装フローと記録のルール）を導入し、
  `docs/knowledge.md`（知見。`CLAUDE.md` から自動読み込み）と
  `docs/worklog.md`（この時系列ログ）を追加した。
- `trip_planner` の `CLAUDE.md` にある `@AGENTS.md` は外してある。あちらは
  `next dev` が生成する Next.js 向けの注意書きで、このリポジトリには当てはまらない
  （ビルドも依存パッケージも無い素の ES モジュール）。
- 知見の初期内容は README と `js/` の実装から書き起こした。日付の扱い・二重保存・
  移行を一度きりにしている理由・`sw.js` の `VERSION`・相対パスなど、
  読まないと踏む落とし穴を中心に入れてある。

## 2026-09-19 データの永続化を強化 (#1)

- IndexedDB を主ストレージにし、localStorage を複製として残す二重持ちにした（`a49d4ba`）。
  `navigator.storage.persist()` でブラウザの自動削除を防ぎ、File System Access API で
  保存先ファイルを決めておくと変更のたびに自動で書き出すようにした。
  「データの保存状態」の画面と、14 日以上バックアップしていないときのお知らせも追加。
  → 知見「保存は『二重持ち・片方が落ちても続ける』」
  「localStorage からの移行は一度きり」「自動バックアップ先の『ハンドル』は IndexedDB にしか置けない」

## 2026-09-19 ポイント管理PWAを追加 (#1)

- 各サイトのポイント数と有効期限を手動で登録して管理する PWA の初期実装（`aed5e3b`）。
  ビルド不要・依存パッケージなしのバニラ JavaScript。期限の色分け、単位ごとの集計、
  検索・絞り込み・並び替え、JSON バックアップ、失効前の通知、ライト／ダーク切り替え。
  → 知見「日付は『ローカルタイムの YYYY-MM-DD』で扱う」「外から入ってきたデータは
  必ず `sanitizeEntry` を通す」「画面には文字として差し込む」
