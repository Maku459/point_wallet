# ポイントウォレット

各サイトのポイント数と有効期限を **手動で登録** して管理する PWA です。
ビルド不要・依存パッケージなしのバニラ JavaScript で作られており、スマホのホーム画面に追加すればオフラインでも動きます。

## 主な機能

| 機能 | 内容 |
| --- | --- |
| 手動登録 | サイト名・ポイント数・単位・有効期限・カテゴリ・URL・メモを登録／編集／削除 |
| 期限の可視化 | 「あと◯日」を自動計算し、失効済み・7日以内（赤）・30日以内（橙）・余裕あり（緑）で色分け |
| サマリー | 単位ごとの保有合計と、30日以内に失効するポイントを表示（失効済みは合計から除外） |
| 期限警告 | 7日以内に失効するポイントがあれば一覧上部にバナー表示 |
| 検索・絞り込み | サイト名／カテゴリ／メモの横断検索、状態・単位での絞り込み、4種類の並び替え |
| 期限の入力補助 | 「1か月後」「1年後」などのボタンでワンタップ入力、「期限なし」にも対応 |
| バックアップ | JSON ファイルで書き出し／読み込み（機種変更やバックアップに利用） |
| 失効前の通知 | 許可すると、アプリを開いたときに失効間近のポイントを通知（1日1回まで） |
| 表示設定 | ライト／ダーク／端末設定に追従の3モード。絞り込みや並び順も記憶 |
| データの永続化 | IndexedDB に保存し、localStorage にも複製。ブラウザへ自動削除の防止を要求し、保存状態を画面で確認できる |
| 自動バックアップ | 保存先ファイルを決めておくと、変更のたびに自動で書き出し（対応ブラウザのみ） |
| PWA | ホーム画面に追加、オフライン起動、新バージョンの更新通知 |

## データの永続化

データは **端末のブラウザ内にのみ保存** され、外部に送信されることはありません（サーバーもアカウントも不要）。
そのうえで、消えにくくするために4段構えにしています。

1. **IndexedDB を主ストレージに使用**
   localStorage（約5MB）より容量が大きく、ブラウザの永続化要求の対象になります。
2. **localStorage へ同じ内容を複製**
   どちらか一方が失われても、次回起動時にもう一方から自動で復元し、書き戻します。
3. **`navigator.storage.persist()` で自動削除を防止**
   空き容量が不足したときにブラウザがデータを勝手に削除しないよう要求します。Chrome ではホーム画面に追加していると許可されやすく、**インストールして使うのが最も確実**です。
4. **ファイルへの自動バックアップ**（パソコンの Chrome / Edge）
   保存先ファイルを一度決めておくと、登録・編集のたびに同じファイルへ自動で書き出します。

現在の状態はメニューの **「データの保存状態」** から確認できます（保存先・自動削除の防止・使用容量・最終バックアップ）。
14日以上バックアップしていない場合は、起動時にお知らせします。

### それでも消えるケース

- ブラウザの「サイトデータ（Cookie とサイトデータ）を削除」を実行したとき
- 端末の初期化、アプリのアンインストール
- プライベートブラウジングでの利用（タブを閉じると消えます）
- iOS の Safari でホーム画面に追加せずに使い、7日以上開かなかったとき

**定期的に JSON バックアップを保存してください。** 別の端末へ移すときは、書き出した JSON を移行先で「バックアップを読み込む」から取り込みます。同じ登録は更新日時が新しい方が残ります。

## 使い方

1. 右下の **＋** ボタンから、サイト名とポイント数を入力します（この2つが必須）。
2. 有効期限は日付を直接入れるか、「1か月後」などのボタンで入力します。期限がないポイントは「期限なし」にチェックします。
3. 一覧のカードをタップすると編集・削除ができます。削除直後に表示される「元に戻す」で取り消せます。
4. 右上の **⋮** からバックアップ、通知設定、サンプルデータの追加ができます。

## ローカルで動かす

Service Worker は `file://` では動かないため、簡易サーバー経由で開きます。

```bash
npm start           # http://localhost:8000 で配信（Node.js のみ、依存パッケージなし）
```

`PORT=3000 npm start` のようにポートを変更できます。

## テスト

日付計算・状態判定・入力検証・集計・バックアップの統合処理を Node.js の標準テストランナーで検証しています。

```bash
npm test
```

## 公開（GitHub Pages）

PWA としてホーム画面に追加するには HTTPS で配信する必要があります。GitHub Pages を使う場合：

1. リポジトリの **Settings → Pages → Source** で **GitHub Actions** を選ぶ。
2. `main` ブランチに push すると `.github/workflows/pages.yml` が実行され、公開されます。
3. 公開された URL をスマホで開き、ブラウザのメニューから「ホーム画面に追加」を選びます。

`start_url` と `scope` は相対パス（`.`）なので、`https://<ユーザー名>.github.io/point_wallet/` のようなサブディレクトリ配信でもそのまま動きます。

## ファイル構成

```
index.html              画面の構造
css/styles.css          スタイル（ライト／ダーク対応）
js/core.js              日付計算・状態判定・集計・検証（DOM 非依存）
js/db.js                IndexedDB・永続化要求・自動バックアップ先の保持
js/store.js             保存と読み出し（IndexedDB ＋ localStorage）とバックアップ処理
js/app.js               画面の組み立てと操作
sw.js                   オフライン用 Service Worker
manifest.webmanifest    PWA の設定
icons/                  アプリアイコン
tools/serve.js          開発用の簡易静的サーバー
tests/                  core.js / store.js のテスト
```

## 補足

- 更新時は `sw.js` の `VERSION` を変えるとキャッシュが入れ替わり、利用者に更新通知が出ます。
- 通知はサーバーを使わない仕組みのため、アプリを開いたときにのみ表示されます（閉じている間のプッシュ通知は行いません）。
- 旧バージョン（localStorage のみ）で登録したデータは、初回起動時に IndexedDB へ自動で移行されます。移行は一度だけ行われるため、削除した登録が復活することはありません。
